# 更新日志

## 0.3.0 · UE 5.7.4–5.8.4

### 版本支持

- 当前版本支持 UE 5.7.4 和 5.8.4。
- 历史版本支持在 0.1.x（UE 5.4.4–5.8.4）；本次更新包含对其的修复。
- 更多 soloAS 信息请访问：[soloAS 首页](https://soloas.cuviss.com/zh/)、[使用文档](https://soloas.cuviss.com/docs/zh/overview.html)。

### 新增功能

- 功能模组：将玩法组织为可独立加载、卸载和更新的模组，支持随项目发布或由玩家安装。
- 在编辑器中创建模组、编辑清单和检查依赖；通过项目配置控制外部模组可使用的接口，并支持官方模组签名验证。

### 修复

- 蓝图结构体资源缺失时不再崩溃。
- 跨脚本文件继承的接口默认方法在热重载后会更新。
- 不安全的接口变更会给出明确提示，并保留现有代码。
- 修复部分插件组合在 Unity 编译下的名称冲突。
- 原生调用模块加载失败时不再导致编辑器崩溃。（也纳入 0.1.x）
- 预编译包安装到 C++ 项目后，首次构建不再重新编译 soloAS 插件。

### 其他说明

- VS Code 扩展 soloAS 0.3.0 同步发布。

## 0.2.1 · UE 5.7.4–5.8.4

### 版本支持

- 当前版本支持 UE 5.7.4 和 5.8.4。
- 历史版本支持在 0.1.x（UE 5.4.4–5.8.4）；本次更新不包含对其的修复。
- 更多 soloAS 信息请访问：[soloAS 首页](https://soloas.cuviss.com/zh/)、[使用文档](https://soloas.cuviss.com/docs/zh/overview.html)。

### 新增功能

- VS Code 中现在可以补全蓝图父类成员和接口方法，并查看相应悬停信息。
- MCP 编辑支持批量修改和显式编译；AI 助手中断后，可从 MCP 或编辑器菜单继续编译。
- VS Code 扩展市场中的 **soloAS** 扩展同步发布 0.2.1。
- VS Code 扩展新增接口和 lambda 语法支持；类型信息载入或重新打开文档后，诊断信息会刷新；lambda 回调断点可停在正确的调用帧。

### 修复

- 修复在 lambda 回调内命中断点时，调试器无法停在对应回调帧的问题。
- 修复热重载蓝图父类时可能发生的编辑器崩溃；按文档继承蓝图父类时，无需显式声明 `import`。
- 修复在同一模块内修改父接口的默认方法后热重载时，实现类无法获取新默认方法的问题。
- 修复在 Windows 上以默认 Unity 方式从源码编译插件时因名称冲突而失败的问题。

### 其他说明

- 已知问题：父接口和实现类分属不同模块时，热重载后实现类不会刷新；需要重启编辑器，或重新编译实现类所在的模块。

## 0.2.0 · UE 5.7.4–5.8.4
<!-- generated-release-heading:end -->

### 版本支持

- 当前版本支持 UE 5.7.4 和 5.8.4。
- 历史版本支持在 0.1.x（UE 5.4.4–5.8.4）；本次更新不包含对其的修复。
- 更多 soloAS 信息请访问：[soloAS 首页](https://soloas.cuviss.com/zh/)、[使用文档](https://soloas.cuviss.com/docs/zh/overview.html)。

### 新增功能

- 脚本可以实现 C++、AS 和蓝图接口；编辑器脚本还能新建接口供蓝图调用和实现；新建脚本接口暂不支持打包和预编译。
- 脚本类可以继承蓝图父类，并能调用已有蓝图对象的函数和读写其属性；脚本类继承某个蓝图期间，对该蓝图的结构性修改会受到保护。
- 脚本可以使用在项目配置中登记的蓝图结构体。
- 重写原生事件时，脚本可以调用父类的原始实现。
- 委托和容器算法支持使用 lambda 及显式变量捕获。
- 在「项目设置 → 插件 → soloAS 打包」设置脚本交付方式和输出目录，通过 SoloAS 菜单跳转到设置页、UE 打包设置和项目启动器。
- 字节码打包可不分发 AS 源码并减少启动编译；半 AOT 可将适用的脚本函数编译进游戏以减少虚拟机开销。
- 命令行与 CI 可以使用项目设置和打包方案检查、执行及查询打包；soloAS 命令行打包支持 Win64。
- 通过 MCP 让 AI 查询脚本类型和工程信息、协助调试和打包，并可从 SoloAS 菜单复制项目连接配置。
- C++ 工具链功能可检测和选择可用工具链，协助准备 C++ 构建。
- SoloAS 菜单支持中文和英文。

## 0.1.3 · UE 5.4.4–5.8.4
<!-- generated-release-heading:end -->

### 版本支持

- 当前版本支持 UE 5.4.4–5.8.4。
- 更多 soloAS 信息请访问：[soloAS 首页](https://soloas.cuviss.com/zh/)、[使用文档](https://soloas.cuviss.com/docs/zh/overview.html)。

### 新增功能

- soloAS 菜单新增「关于 soloAS」「检查更新」与一键更新，方便查看版本和更新；更新会保留插件内用户配置，失败时自动回滚。
- 补齐部分 UE 原生插件的脚本 API，包括 TextureGraph 和 ChaosCloth，并对齐相关函数的引用参数和返回值，与 UE-AS fork 一致。

### 修复

- AS 脚本 API 完善：以 UE 5.8.4 时期 UE-AS fork 的 AS 插件为基准，修复少数不常用接口的细节差异；原生函数非空 FName 默认值等上游缺陷按修复后的行为提供。
- 修复调用原生函数时，引用与输出参数未直接传递调用方地址、非 const 裸引用参数的输入值丢失，可能导致崩溃的问题。
- 修复导出脚本文档后编辑器关闭时可能发生崩溃的问题。
- 修复脚本基类在 default 中设置原生属性、蓝图子类覆盖该属性时，实例错误使用脚本默认值的问题；蓝图覆盖现可正常生效。
- 修复在编辑器中删除或恢复脚本文件、反复热重载时旧脚本模块不断累积的问题。删除父类后再新建其蓝图子类对象不再崩溃，并会应用仍存在的脚本祖先的默认值。
- 修复脚本 Actor 类使用 default 设置组件或属性时，蓝图子类对继承组件和属性的修改未正确出现在放置和生成的实例上的问题，与 UE-AS fork 一致。修复前已保存的关卡可能已写入旧值，需要在关卡里重新检查这些属性。
- 修复脚本类继承 Widget 或动画蓝图时，蓝图设计器或动画图功能可能缺失的问题。
- 修复 macOS 编辑器中脚本类重定向识别异常的问题（仅影响 macOS）。
- 修复项目测试配置无法覆盖插件默认值的问题。
- 修复打包时脚本源码存放方式与 UE-AS fork 不一致的问题。
- 修复脚本省略原生函数的非空 FName 默认参数时可能传入空名称的问题。
- 修复原生枚举中超出有符号 8 位范围的常量未向脚本公开的问题。
- 修复部分原生函数的输出参数、常量引用、默认参数和返回引用与原生声明不一致的问题。
- 修复部分原生接口、通配函数和委托参数无法正确供脚本使用的问题。
- 修复部分编辑器类型未被发现和绑定的问题。
- 修复删除脚本类后重新创建同名类可能出现的问题。
- 修复热重载时新对象可能被误认为旧对象的问题。
- 修复热重载后调试服务器查询函数信息时可能发生崩溃的问题。
- 修复编译蓝图或加载资产后，StateTree 脚本节点可能从节点列表消失的问题。

### 变化

- 插件脚本根目录仅收集已启用且声明 `CanContainContent` 的插件；未声明该选项的插件中的 `Script` 目录不再加载，与 UE-AS fork 一致。
- `System::SetTimer` 现在要求显式传入 `bLooping`；已有脚本请补上 `true` 或 `false`，与 UE-AS fork 一致。
- 碰撞对象查询掩码改用 `int32` 和 `ObjectTypesToQuery` 字段；使用旧 `int64` 构造或 Get/Set 方法的脚本需要调整，与 UE-AS fork 一致。
- `FInputActionValue` 的 `*=` 仍会修改原值，但表达式返回副本，不再返回引用，与 UE-AS fork 一致。
- `InputModifier.ModifyRaw` 不再声明为 const；使用相关接口的脚本需要调整，与 UE-AS fork 一致。

### 移除功能

- 移除菜单中的蓝图快速调用扫描、完整重载脚本和打开日志入口（属于后续扩展功能，暂不保留）。
- 启动时不再自动提示引擎版本为空的资产（冗余，暂不保留）。
- 移除脚本单元隔离及自动命名空间和单元依赖规则（属于后续扩展功能，暂不保留）。
- 移除旧版蓝图导入配置（属于后续扩展功能，暂不保留）。普通脚本中的 Lambda 不受影响。
- 移除可选的原生属性保留配置（属于后续扩展功能，暂不保留）。
- 移除编辑器脚本接口 `Editor::ImportObjectText`（冗余，暂不保留）。
- 移除了若干面向扩展开发者的内部接口，普通脚本不受影响（属于后续扩展功能，暂不保留）。
- 脚本类实现 C++ 接口但没有重写其中某个函数时，通过接口调用该函数不再自动执行 C++ 的默认实现，而会报错（与 UE-AS fork 一致）。

## Get involved

Communicate through the [soloAS repository](https://github.com/cuviss-open/soloAS).

### Reporting issues

Open an issue in the repository describing the problem and the expected behaviour, with a minimal reproduction.

### Pull requests

Keep changes focused. Explain the user-visible result and how you verified it on stock UE. Changes to Runtime or Bridge should also be checked in a non-editor Game build when applicable. Include the engine version and platform so reviewers can reproduce the result.

### DCO sign-off

Contributions use Developer Certificate of Origin 1.1 (DCO) sign-off. Sign each commit using:

```sh
git commit -s
```

Review the [Developer Certificate of Origin](https://developercertificate.org/) before signing. Use your own contributor identity; signing records your certification for the contribution.

## Contributing and giving back

soloAS is open source. To help the project get something back, we make an attribution request and invite you to share your project; neither is mandatory. You are welcome to report problems and open issues in the [repository](https://github.com/cuviss-open/soloAS), and more contributors are welcome.

### Attribution request

If your project uses soloAS, we would appreciate a note saying "Uses soloAS" in your credits, store page, README or website, with a link to the [soloAS website](https://soloas.cuviss.com) or [repository](https://github.com/cuviss-open/soloAS). This is not a license requirement; we simply value the gesture.

### Showcase

If a public project states that it uses soloAS, we may list it as a showcase, showing only its name, a short description and public screenshots or links, never in a misleading way. Owners can ask for changes or removal at any time. You are also welcome to let us know that your project can be showcased.
